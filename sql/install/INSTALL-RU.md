# UnaWaiter — пилотная установка на продакшн (MIRON COSTIN)

Сопроводительный документ для того, кто запускает скрипты. Знание проекта не
требуется.

## Структура пакета

```
INSTALL-RU.md             ← этот документ, прочитайте первым
INSTALARE-PILOT.md          то же самое на румынском
install/                  ← шаг 1: база ресторана
  install_front.bat         оркестратор (запускает 00…99 по порядку)
  verify_front.bat          проверка, ничего не меняет
  98_dezinstalare.sql       очистка, если нужна повторная попытка
  seed/seed_11.sql          столы и зоны филиала 11
backoffice/
  vuw_all/                ← шаг 2: представления и триггеры
  forme/                  ← шаг 3: две формы в Конфигураторе
```

> ⚠️ **Комментарии внутри скриптов и все сообщения на экране — на румынском.**
> В конце документа есть словарь сообщений, которые вы можете увидеть.

---

## Что устанавливает этот пакет

UnaWaiter — Android-приложение для официантов: принимают заказ за столом,
отправляют на кухню и, при необходимости, проводят оплату с фискальным чеком.
Заказы попадают в UAMenu как любые другие — приложение не является параллельной
системой.

Скрипты добавляют в Oracle слой, необходимый приложению: пять собственных таблиц,
три представления и PL/SQL-пакет в базе ресторана, плюс несколько представлений и
две формы в бэк-офисе.

## Область этой поставки

**Только филиал 11 — MIRON COSTIN (Рышкановка), `93.116.209.117/xe`.**

Columna и Mircea cel Bătrîn **пока установить нельзя**: у нас нет реальных номеров
столов и их распределения по зонам (см. последний раздел). Если установку всё же
запустить для них, она остановится сама с ошибкой `ORA-20092` и сообщением о том,
чего не хватает — незавершённой установки не останется.

## Что мы гарантируем

**Ни один существующий объект не изменяется.** Все новые объекты имеют префикс
`UW_` или `VUW_`. Заказы пишутся через `VMDB_COMENZ_RESTAURANT` — тот же путь,
которым пользуется UAMenu, с его триггерами, а не напрямую в таблицы. UAMenu
продолжает работать параллельно, без изменений.

**Установка останавливается на первой ошибке** (`WHENEVER SQLERROR EXIT FAILURE`)
и пишет полный лог в `log\install_<cod_univ>_<дата>.log`.

**Есть полное удаление**, если понадобится вторая попытка:

```bat
sqlplus unirest/unirest@93.116.209.117:1521/xe @98_dezinstalare.sql DA-STERG
```

Аргумент `DA-STERG` обязателен именно для того, чтобы скрипт нельзя было запустить
по привычке. Удаляет только наши объекты; не трогает заказы, меню, официантов в
`VMS_UNIVERS` и смену в `TMDB_SOLD`.

## Перед началом

Предварительные условия проверены на всех трёх продакшн-базах (права, кодировка
`CL8MSWIN1251`, место, `DBMS_LOCK`, пакеты UAMenu, от которых мы зависим) —
готовить ничего не нужно.

Одно **рекомендуется**: обновить справочники базы ресторана (список персонала и
меню). Это materialized views с ручным обновлением, а в Miron Costin последнее —
от 1 июля. Официант, принятый после этой даты, не появится в приложении и не
сможет войти, без какого-либо объясняющего сообщения.

### Кодировка

Скрипты в **UTF-8 без BOM**. Файлы `.bat` сами выставляют
`NLS_LANG=AMERICAN_AMERICA.AL32UTF8`; для шагов 2 и 3, запускаемых напрямую из
`sqlplus`, выставьте её в консоли заранее.

Но от этого **не зависит корректность данных**: все кириллические строки, которые
реально попадают в базу, записаны через `UNISTR` с escape-последовательностями,
то есть сами файлы в этих местах — чистый ASCII. Это `Общая` (имя группы свойств
в Конфигураторе), названия двух форм и русские названия зон. Даже если клиент
окажется в другой кодировке, данные не испортятся — пострадает максимум вид
сообщений в консоли.

Значения escape-последовательностей сгенерированы из исходных строк и сверены с
данными, уже корректно лежащими в базе.

## Шаги, по порядку

### 1. База ресторана

```bat
install_front.bat 93.116.209.117 11
```

Выполняет по порядку: таблицы → начальные данные (зоны и столы) → внешние ключи →
представления → пакет → проверка. Порядок не произвольный: внешний ключ
столы→зоны создаётся поверх уже вставленных строк, поэтому должен идти после
начальных данных.

Устанавливаемые столы: **35 — Зал 1–15, Терраса 16–35**. Номера взяты из реальных
заказов ресторана. Распределение по зонам не окончательное и **не требует
программиста**: меняется в форме «Amplasare mese» (Размещение столов) в бэк-офисе.

В конце должно быть напечатано `REZULTAT: TOTUL E PE LOC` («РЕЗУЛЬТАТ: ВСЁ НА
МЕСТЕ»).

### 2. Бэк-офис — представления и триггеры

```bat
sqlplus foishor/<пароль>@una.md:4024/cloudbd.world @00_install_vuw_all.sql 11
```

Аргумент — список установленных филиалов. Для пилота: `11`. Когда добавятся
Columna и Mircea — та же команда с `11,13,17`.

> ⚠️ **Не запускайте `01_views.sql` отдельно.** `CREATE OR REPLACE VIEW` удаляет
> триггер `INSTEAD OF`, и без него формы показывают данные, но любое сохранение
> падает с `ORA-01733` — из этого сообщения невозможно догадаться, что не хватает
> триггера. Скрипт `00_` выполняет оба за один проход; используйте его.

> ⚠️ **База ресторана должна быть запущена** в момент выполнения. Oracle
> разрешает db link уже при создании представления, а не при запросе.

### 3. Бэк-офис — формы

```bat
sqlplus foishor/<пароль>@una.md:4024/cloudbd.world @install_forme.sql
```

Создаёт «Chelneri UnaWaiter» (Официанты UnaWaiter) и «Amplasare mese» (Размещение
столов). `obj_id` выбираются автоматически (`MAX+1`), поэтому конфликт с
существующими объектами невозможен, а если формы уже есть — скрипт откажется
работать с `ORA-20080`, вместо того чтобы что-то перезаписать.

**После установки — три шага, по порядку:**

1. перезапустить `UniacCLNT.exe`;
2. открыть каждую форму **и закрыть её один раз** — при первом открытии
   генерируются колонки таблиц;
3. выполнить `fix_grid_cols.sql` (из той же папки).

Шаг 3 **не опционален**: при закрытии формы клиент сохраняет пустой список
колонок, а при следующем открытии доверяет ему — таблица открывается без
заголовков и выглядит пустой. Удаление строки не помогает, она перезаписывается
так же при следующем закрытии; скрипт записывает корректный список.

### 4. Приложение и сервер

PHP и APK делаем мы. В этот пакет они не входят.

## Проверка, в любой момент

Ничего не меняет, можно запускать сколько угодно раз:

```bat
verify_front.bat "unirest/unirest@93.116.209.117:1521/xe" 11
```

Проверяет таблицы, индекс по зонам, валидность пакета, доступ к `DBMS_LOCK`, и
даже вызывает функции приложения, чтобы убедиться, что они возвращают столы и меню.

## Если что-то упало

Пришлите нам файл из `log\`. В нём всё: команда, ошибка и шаг, на котором
остановилось.

## Что нам нужно от вас для Columna и Mircea cel Bătrîn

Для каждого из двух ресторанов:

1. **Реальные номера столов.** По заказам видны некоторые закономерности, но это
   предположения, а не факты: в Columna нумерация похожа на группы (`11–16`,
   `21–26`, `31–35`), в Mircea — `1–24`. Встречаются также номера, использованные
   один раз (`121`, `222`, `2088`), похожие на опечатки — но подтвердить должны вы.
2. **Распределение по зонам** (зал, терраса, этаж…). База не знает, какой стол на
   улице: `DESK` — это просто число, без справочника в UAMenu. Группы в Columna
   наводят на мысль о **трёх зонах**, а не двух — требуется подтверждение.
3. **В Mircea стол `0`** встречается в 15 заказах. Если это реальный стол, скажите
   нам: сейчас он не может быть использован из приложения.

С этими данными мы напишем файл начальных данных для каждого филиала (по образцу
`seed/seed_11.sql`), и установка пройдёт точно так же.
